# Plant V1 行为映射

## 1. 目的

本文档定义 Plant V1 的产品行为如何映射到机械动作、灯光和振动。行为层只使用语义名称；角度、PWM、GPIO、持续时间细节和硬件极性由 Motion、Lighting、Haptic Service 及其 Adapter 处理。

本文档中的时间是产品体验目标，不是硬实时接口参数。最终数值可在硬件联调后调整，但行为意图不得由 Adapter 擅自改变。

## 2. V1 行为总表

| 行为 | 典型触发 | Motion 语义 | Lighting 语义 | Haptic 语义 | 结束状态 | 可被普通事件中断 |
| --- | --- | --- | --- | --- | --- | --- |
| `WakeUp` | 休眠时单击、BLE 唤醒 | `Wake` | `FadeIn` 后 `SoftBreathing` | `SoftPulse` | `Idle` | 否，仅停止或故障 |
| `Happy` | 空闲时单击、BLE 命令 | `GentleSway` | `SoftBreathing` | `DoubleSoftPulse` | `Idle` | 是 |
| `Attention` | BLE 连接成功或明确命令 | `LookUp` | `ShortPulse` | `SoftPulse` | `Idle` | 是 |
| `Calm` | 明确命令、互动收尾 | `ReturnNeutral` | `SlowBreathing` | `Off` | `Idle` | 是 |
| `Sleep` | 长按、BLE 命令、空闲超时 | `MoveToSleepPose` | `FadeOut` | `SoftPulse` | `Sleeping` | 否，仅唤醒、停止或故障 |
| `Error` | 不可恢复故障 | `StopAndHoldSafe` | `ErrorBlink` | `Warning` 后停止 | `Fault` | 否，仅复位 |

## 3. 行为分解

### 3.1 WakeUp

产品意图：植物从休眠中被用户叫醒，反馈应柔和但明确。

推荐时序：

1. 立即开始一次轻振动和灯光渐亮，满足响应延迟要求。
2. 舵机从休眠姿态平滑移动到中立姿态。
3. 灯光进入柔和呼吸模式。
4. 运动完成后结束行为并进入 `Idle`。

约束：

- 不得突然跳到目标角度。
- 已处于正常唤醒状态时再次请求 `WakeUp`，应返回成功但不重播。

### 3.2 Happy

产品意图：植物对用户触摸作出积极、亲近的回应。

推荐时序：

1. 两次轻振动形成可辨认的触觉标记。
2. 舵机围绕中立姿态完成两次幅度较小的左右摇摆。
3. 灯光在整个动作期间保持柔和呼吸。
4. 舵机回到中立姿态，行为结束并进入 `Idle`。

约束：

- 摇摆不得触及舵机安全行程边界。
- 任何时刻接收到停止、睡眠或故障事件，都应按优先级结束该行为。

### 3.3 Attention

产品意图：植物短暂地提醒用户“我注意到了”。

推荐时序：

1. 灯光快速但不刺眼地脉冲一次。
2. 一次轻振动。
3. 舵机轻微抬起并回到中立姿态。
4. 行为结束并进入 `Idle`。

约束：BLE 连接频繁抖动时不得连续重播；Communication Service 应进行状态去重。

### 3.4 Calm

产品意图：从活跃表现平稳回归安静状态。

推荐时序：

1. 停止现有振动。
2. 舵机平滑回到中立姿态。
3. 灯光切换为慢速呼吸。
4. 运动完成后结束行为并进入 `Idle`。

### 3.5 Sleep

产品意图：植物收拢并安静休息。

推荐时序：

1. 一次轻振动确认休眠请求。
2. 舵机平滑移动到配置的休眠姿态。
3. 灯光同步渐暗，在运动完成时关闭。
4. 行为结束并进入 `Sleeping`。

约束：

- 休眠姿态必须位于安全行程内。
- `Sleeping` 状态下除触摸检测和 BLE 唤醒所需能力外，其余输出保持关闭。
- 完成 `Sleep` 行为后默认进入轻睡眠；达到配置的深睡眠超时且满足安全条件时可进入深睡眠。
- 深睡眠会关闭 BLE，不能再由手机唤醒；此状态必须能由触摸输入 GPIO 唤醒。

### 3.6 Error

产品意图：明确表达设备异常，同时优先保证机械安全。

推荐时序：

1. 立即取消当前运动序列并让舵机进入安全保持或安全释放状态，具体策略由硬件设计决定。
2. 立即停止普通振动序列，可播放一次有限时长的警告振动。
3. 灯光进入低亮度错误闪烁模式。
4. 生命周期进入 `Fault`。

约束：

- 错误表现自身不得无限驱动振动马达。
- `Fault` 状态只接受状态查询、诊断查询和明确的复位操作。
- 如果灯光子系统自身故障，不能因无法显示错误模式而阻塞故障处理。

## 4. 触摸到行为映射

| 当前生命周期 | 输入 | 条件 | 结果 |
| --- | --- | --- | --- |
| `Sleeping` | 单击 | 触摸有效 | 执行 `WakeUp` |
| `Idle` | 单击 | 触摸有效 | 执行 `Happy` |
| `Interacting` | 单击 | 当前行为可中断 | 中断当前行为并执行 `Happy` |
| `Interacting` | 单击 | 当前行为不可被普通事件中断 | 忽略并记录原因 |
| `Idle` / `Interacting` | 长按 | 达到长按阈值 | 执行 `Sleep` |
| `Sleeping` | 长按 | 达到长按阈值 | 执行 `WakeUp` |
| `Booting` | 任意触摸 | 初始化未完成 | 忽略，不缓存 |
| `Fault` | 任意触摸 | 未复位 | 忽略 |
| `Updating` | 任意触摸 | OTA 尚未结束 | 忽略，不缓存 |

## 5. BLE 命令到行为映射

| 命令 | 允许状态 | 结果 |
| --- | --- | --- |
| `SetBehavior(WakeUp)` | `Sleeping`、`Idle` | 唤醒或幂等成功 |
| `SetBehavior(Happy)` | `Idle`、可中断的 `Interacting` | 执行 `Happy` |
| `SetBehavior(Attention)` | `Idle`、可中断的 `Interacting` | 执行 `Attention` |
| `SetBehavior(Calm)` | `Idle`、可中断的 `Interacting` | 执行 `Calm` |
| `SetBehavior(Sleep)` | `Idle`、`Interacting`、`Sleeping` | 执行休眠或幂等成功 |
| `StopBehavior` | `Interacting` | 停止表现并回到安全中立状态 |
| `ResetFault` | `Fault` | 重新执行受控初始化；成功后进入 `Idle` |

在 `Booting` 状态收到行为命令时返回 Busy。在 `Fault` 状态收到非查询、非复位命令时返回 InvalidState。
在 `Updating` 状态收到普通行为命令时返回 Busy；取消升级、查询状态和故障事件仍可处理。

## 6. OTA 与行为协调

OTA 不是产品行为，而是生命周期流程。系统接受通过前置校验的 OTA 开始请求后：

1. 停止可中断行为。
2. 将舵机移动到安全休眠姿态。
3. 关闭灯光和振动输出。
4. 进入 `Updating`，禁止自动休眠和深睡眠。
5. 升级成功后受控重启；取消或传输失败时回到当前有效固件的 `Idle` 状态。

如果安全姿态无法确认，设备不得开始写入升级分区，并应返回明确错误。升级过程发生不可恢复的 Flash 或镜像错误时进入 `Fault`；普通传输中断不应触发机械错误表现。

## 7. 行为完成与失败事件

行为编排至少处理以下异步事件：

- `MotionCompleted`
- `MotionFailed`
- `LightingPatternCompleted`
- `HapticPatternCompleted`
- `BehaviorTimeout`
- `StopRequested`
- `FaultRaised`

行为不得通过轮询等待执行器完成。完成事件由 Adapter 经对应 Service 转换后投递给系统执行上下文。

任一关键运动步骤失败时，当前行为失败并进入 `Error`。非关键灯光或振动失败应记录诊断信息；是否升级为 `Fault` 由错误分类策略决定。

## 8. 默认体验参数

以下参数用于模拟器和首轮硬件联调，不直接写入 Behavior 枚举：

| 参数 | 初始建议值 | 允许调整范围 |
| --- | --- | --- |
| 单击防抖时间 | 80 ms | 40–200 ms |
| 长按阈值 | 2000 ms | 1000–5000 ms |
| 自动休眠时间 | 5 min | 1–60 min，或禁用 |
| 深睡眠等待时间 | 30 min | 5 min–24 h，或禁用 |
| 普通动作总时长 | 0.6–3 s | 由运动 Profile 限制 |
| Happy 摇摆次数 | 2 次 | 1–3 次 |
| 呼吸灯周期 | 2.4 s | 1.5–5 s |
| 错误灯闪烁周期 | 1 s | 0.5–2 s |
| 警告振动总时长 | 不超过 1 s | 最大 2 s |

舵机角度、脉宽和速度值必须在实际机械结构确定后写入产品配置，不在本文档中假定。

## 9. 测试要点

- 每个行为启动后，三个表现通道收到正确的语义 Pattern。
- 行为完成后进入预期生命周期状态。
- 优先级更高的事件能在规定时间内中断当前行为。
- 重复命令满足幂等规则。
- 触摸抖动不会产生重复行为。
- 行为超时能终止未返回完成事件的执行器。
- 任意舵机目标都被限制在已配置安全行程内。
- `Fault` 状态不会继续执行普通动作或无限振动。
- `Updating` 状态不会接受普通行为、进入睡眠或重新启用执行器输出。
- 完成 `Sleep` 后输出通道关闭，并按配置进入轻睡眠或深睡眠。
- 深睡眠关闭 BLE，轻睡眠保留约定的低频广播和唤醒能力。
