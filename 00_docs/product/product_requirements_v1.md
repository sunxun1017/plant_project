# Plant V1 产品需求文档

## 1. 文档信息

| 项目 | 内容 |
| --- | --- |
| 产品名称 | Plant V1 |
| 产品形态 | USB 供电的桌面具身交互植物 |
| 文档状态 | V1 范围基线 |
| 目标平台 | ESP32-C3 |
| 核心原则 | 行为是产品，硬件是行为的执行器 |

本文档定义 Plant V1 的产品范围、交互闭环和验收标准。未列入 V1 范围的能力，不应阻塞首版交付。

## 2. 产品目标

Plant V1 是一个能够感知用户触摸，并通过机械动作、灯光和振动表达状态的桌面互动植物。用户也可以通过手机 BLE 控制植物行为和查询设备状态。

V1 要验证以下核心价值：

1. 用户能自然地通过触摸与植物互动。
2. 植物能用动作、灯光和振动形成一致、可辨认的反馈。
3. 手机能可靠地控制行为并读取设备状态。
4. 所有动画和运动均为非阻塞执行，设备在表现行为时仍能响应停止和故障事件。
5. 设备可以在不拆机的情况下安全升级固件，并在升级失败后恢复到可用版本。
6. 植物休眠时关闭非必要负载，在保留约定唤醒能力的前提下降低功耗。

## 3. 目标用户与场景

### 3.1 目标用户

喜欢桌面摆件、电子宠物或情绪陪伴型产品，希望获得轻量互动体验的个人用户。

### 3.2 核心场景

#### 场景 A：触摸唤醒

1. 植物处于休眠状态。
2. 用户抚摸触摸区域。
3. 系统恢复主动电源域，并以正常的开心交互回应。
4. 植物完成开心表现后进入空闲状态；用户不需要感知此前是否处于轻睡眠。

#### 场景 B：触摸互动

1. 植物处于空闲状态。
2. 用户抚摸触摸区域。
3. 植物表现开心：轻柔摇摆、柔和呼吸灯、两次轻振动。
4. 行为结束后回到空闲状态。

#### 场景 C：手机控制

1. 用户通过手机或 BLE 调试工具连接设备。
2. 用户选择一个 V1 支持的行为。
3. 设备校验命令、返回接收结果并执行行为。
4. 用户可以查询当前生命周期、行为、执行器状态和最近错误。

#### 场景 D：自动休眠

1. 设备在配置的时间内没有触摸或有效 BLE 命令。
2. 植物播放休眠行为。
3. 灯光熄灭，机械结构回到安全休眠姿态。
4. 触摸或有效 BLE 命令可以再次唤醒设备。

#### 场景 E：故障保护

1. 设备检测到执行器错误、配置错误或内部不可恢复错误。
2. 设备立即停止机械运动和振动。
3. 灯光显示错误模式，并记录错误码。
4. 手机可以读取错误状态；重启或明确的复位命令后才恢复正常运行。

#### 场景 F：无线升级

1. 用户通过已连接的 BLE 客户端发起固件升级。
2. 设备停止当前行为、回到安全姿态并进入升级状态。
3. 设备接收并校验固件，切换启动分区后重启。
4. 新固件自检成功后确认版本；启动失败时自动回滚到上一可用版本。

#### 场景 G：低功耗休眠

1. 设备达到自动休眠条件，完成 `Sleep` 行为并关闭动作、灯光和振动输出。
2. 默认进入保留触摸唤醒和低频 BLE 广播的轻睡眠模式。
3. 达到可配置的深睡眠超时后，设备可关闭 BLE 并进入深睡眠。
4. 轻睡眠可由触摸或 BLE 连接唤醒；深睡眠仅由触摸、定时器、复位或重新上电唤醒。

## 4. V1 功能范围

### 4.1 硬件能力

V1 包含：

- ESP32-C3 主控。
- 一个舵机运动通道。
- 一个 RGB 呼吸灯通道。
- 一个振动马达通道。
- 一个电容触摸输入通道。
- Bluetooth Low Energy 通信。
- USB 常供电。
- 满足双分区升级和回滚要求的 Flash 空间。

所有 GPIO、舵机安全行程、灯光极性和振动强度上限由 BSP 或产品配置提供，不进入行为层。

### 4.2 生命周期

设备必须支持以下生命周期状态：

| 状态 | 说明 |
| --- | --- |
| `Booting` | 初始化硬件、读取配置并执行自检 |
| `Idle` | 可响应触摸和 BLE 命令的正常待机状态 |
| `Interacting` | 正在表现一个产品行为 |
| `Sleeping` | 机械结构处于休眠姿态，灯光关闭 |
| `Fault` | 机械输出已进入安全状态，只接受查询、复位和已加密已绑定链路上的恢复 OTA |
| `Updating` | 执行固件传输、校验或启动分区切换，普通交互暂停 |

`LowBattery` 为后续电池版本预留，不属于 USB 供电 V1 的交付范围。

### 4.3 产品行为

V1 必须实现：

- `WakeUp`
- `Happy`
- `Attention`
- `Calm`
- `Sleep`
- `Error`

`Grow`、`Retract`、`Excited` 和 `LowBattery` 保留为未来行为，不属于 V1 验收范围。

每个行为的具体表现见 [Plant V1 行为映射](behavior_mapping_v1.md)。

### 4.4 触摸输入

V1 支持：

- 抚摸：稳定触摸至少 300 ms 后稳定释放；无论当前是否轻睡，均恢复主动电源域后执行开心行为。
- 防抖：短于最小时长的碰触和电平抖动不产生业务事件；一次有效抚摸只能产生一个业务事件。

V1 不区分双击、滑动、触摸力度和多触点。

### 4.5 BLE 通信

V1 必须支持：

- 广播、连接、断开和重新连接。
- 设置一个受支持的行为。
- 停止当前行为。
- 查询设备状态。
- 查询遥测信息。
- 设置允许修改的产品配置。
- Ping 请求。
- 协议版本和消息合法性校验。
- 查询 OTA 能力、当前版本和升级状态。
- 通过 BLE 分片传输固件、确认分片并报告升级进度。

BLE 回调不得直接控制舵机、灯光或振动马达。通信命令必须转换为系统命令，并由系统执行上下文处理。

手机原生 App 不属于固件仓库的 V1 交付物；V1 可使用通用 BLE 客户端或协议测试工具完成验收。

### 4.6 状态与遥测

状态查询至少返回：

- 固件版本。
- 协议版本。
- 当前生命周期状态。
- 当前行为及其运行状态。
- BLE 连接状态。
- 舵机、灯光和振动通道的逻辑状态。
- 设备启动时长。
- 最近一次错误码。
- 当前功耗模式和最近一次唤醒原因。
- 当前固件版本、可回滚版本和 OTA 状态。

V1 遥测不包含温度、环境光、湿度和电池电量。

### 4.7 配置

V1 可配置项包括：

- 设备名称。
- 自动休眠时间。
- 全局灯光亮度上限。
- 全局振动强度上限。
- 舵机安全最小位置、最大位置和休眠位置。
- 是否允许深睡眠。
- 进入深睡眠前的等待时间。
- 深睡眠定时唤醒周期；设置为零表示禁用定时唤醒。

配置必须经过范围校验后才能持久化。配置缺失或损坏时，设备必须使用安全默认值启动并记录诊断信息。

### 4.8 低功耗

V1 定义两级低功耗模式：

| 模式 | BLE | 唤醒源 | 使用条件 |
| --- | --- | --- | --- |
| 轻睡眠 | 保留低频广播；已连接时维持连接参数允许的节能状态 | 触摸、BLE、定时器、复位 | 默认休眠模式，兼顾手机可发现性 |
| 深睡眠 | 关闭，手机无法发现设备 | 触摸 GPIO、定时器、复位、重新上电 | 达到深睡眠超时且无 BLE 连接、无 OTA、无配置写入 |

低功耗要求：

- 进入任一睡眠模式前，舵机必须到达安全休眠姿态；随后关闭舵机供电或停止保持力，具体方式由机械安全设计决定。
- 睡眠期间 RGB LED 和振动马达必须关闭，触摸唤醒所需电路除外。
- 存在 BLE 连接、OTA、配置持久化或故障处理时不得进入深睡眠。
- 从睡眠唤醒后必须记录唤醒原因，并恢复到 `Booting` 或 `Idle` 的受控初始化流程。
- 默认启用轻睡眠；是否进入深睡眠及其等待时间由配置决定。
- 开发板上的 USB 转串口等非产品负载不计入芯片级功耗验收，整机功耗在 V1 PCB 确定后复测。

### 4.9 OTA 固件升级

V1 使用 BLE 作为 OTA 传输通道，并采用双应用分区方案。

OTA 流程必须支持：

1. 查询设备型号、硬件版本、当前固件版本、协议版本和可用升级空间。
2. 校验升级包的产品型号、硬件兼容性、版本、长度和签名。
3. 分片传输、分片序号校验、进度查询和明确的错误返回。
4. 完整镜像哈希校验通过后，才允许切换启动分区。
5. 新固件首次启动完成自检后确认镜像有效。
6. 新固件无法启动、看门狗复位或未在规定时间内确认时，自动回滚到上一可用版本。

OTA 约束：

- 正式固件必须验证数字签名；签名公钥或其信任根不得通过普通 BLE 配置修改。
- 默认拒绝降级；开发构建可通过编译期配置允许受控降级。
- 进入 `Updating` 前必须中断普通行为、移动到安全姿态并关闭灯光和振动。
- `Fault` 已满足机械输出和振动安全停止的不变量，允许从已加密且已绑定的 BLE 链路直接
  进入恢复 OTA，不再依赖故障执行器完成休眠动作。
- 从 `Fault` 开始的 OTA 若被取消、断连或发生可恢复传输/校验失败，生命周期必须回到
  `Fault`；只有新镜像成功激活并重启后，才能通过新一轮自检离开故障态。
- `Updating` 状态只处理 OTA、状态查询、取消升级和故障事件，不接受普通行为命令。
- 传输中断或镜像校验失败时继续运行当前有效固件，不切换分区；V1 允许从头重新传输，不要求断点续传。
- 写入、校验和分区切换期间禁止进入低功耗模式。
- OTA 协议不得绕过现有 Communication Service、协议校验和系统状态管理。

## 5. 交互与优先级规则

同一时间只允许一个前台行为拥有动作、灯光和振动表现权。

事件优先级从高到低为：

1. 故障保护。
2. OTA 完整性失败或取消升级。
3. 停止命令。
4. 已通过前置校验的 OTA 开始请求。
5. 睡眠或唤醒命令。
6. 用户触摸。
7. 普通 BLE 行为命令。
8. 自动休眠超时。

高优先级事件可以中断低优先级行为。被中断的行为不自动恢复，设备进入新事件规定的状态。

重复收到与当前行为相同的命令时，设备返回成功，但不重新启动该行为；协议明确要求重播时除外。

## 6. 安全与可靠性要求

- 舵机只能在已校准的安全行程内运动。
- 开机初始化完成前不得产生不可控机械运动。
- 故障和停止命令必须使机械运动与振动进入安全状态。
- 所有灯光、振动和动作序列必须非阻塞执行。
- 系统在表现行为期间仍须处理触摸、BLE 停止命令和故障事件。
- 配置写入中断后，设备必须能够使用上一次有效配置或安全默认值启动。
- OTA 写入或切换过程中断电后，设备必须从当前有效镜像或上一已确认镜像启动。
- 深睡眠前必须确认没有正在进行的 Flash 写入。
- 日志不得包含可用于追踪用户的永久唯一标识或未声明的个人数据。
- V1 不采集、不上传个人数据，也不依赖云服务。

## 7. 性能要求

在硬件能力允许且系统未处于故障状态时：

- 有效抚摸确认到可见或可感知反馈开始：不超过 150 ms。
- BLE 命令接收完成到应答：不超过 200 ms。
- BLE 行为命令接收完成到行为开始：不超过 300 ms。
- 停止命令到舵机和振动停止：不超过 200 ms。
- 从轻睡眠确认有效抚摸到反馈开始：不超过 300 ms。
- 生产硬件在低频 BLE 广播的轻睡眠模式下，3.3 V 主电源轨平均电流目标不超过 5 mA。
- 生产硬件在 BLE 关闭的深睡眠模式下，3.3 V 主电源轨平均电流目标不超过 500 μA。
- OTA 升级过程必须持续报告进度或可查询状态，不得无状态停滞超过 5 秒。
- 设备连续运行 24 小时不得出现任务失联、看门狗复位或行为状态锁死。

精确电机脉冲和 LED 动画节拍由硬件外设、定时器或状态机推进，不得通过业务线程中的延时循环实现。

## 8. V1 验收标准

V1 完成必须同时满足：

1. 上电后设备完成自检并进入 `Idle`，或在失败时进入 `Fault`。
2. 休眠状态抚摸触摸区域能完成无感唤醒并表现 `Happy`。
3. 空闲状态抚摸触摸区域能完整表现 `Happy` 并返回 `Idle`。
4. BLE 客户端可以执行行为、停止行为、查询状态、读取遥测和修改允许的配置。
5. 行为表现符合行为映射表，三个输出通道之间的时序协调可辨认。
6. 当前行为可以被停止、休眠、唤醒和故障事件按优先级中断。
7. 舵机命令不会越过配置的安全行程。
8. 无效协议消息和越界配置不会触发执行器动作，并返回明确错误。
9. 单元测试覆盖行为映射、生命周期转换、命令优先级和配置校验。
10. 使用 Fake Adapter 的 PC 集成测试可以复现触摸唤醒、触摸互动、BLE 控制、自动休眠和故障保护流程。
11. 目标硬件通过连续 24 小时稳定性测试。
12. 设备能在正常状态和 `Fault` 恢复路径中通过 BLE 完成合法签名固件升级，并在新固件
    自检后确认版本；故障恢复传输取消或失败后仍保持 `Fault`。
13. 非法签名、错误型号、损坏镜像和降级包均被拒绝，且当前有效固件仍可启动。
14. 模拟 OTA 传输中断、写入中断和新固件首次启动失败时，设备能够保留或回滚到可用版本。
15. 休眠时舵机、灯光和振动输出关闭，轻睡眠与深睡眠的唤醒源符合定义。
16. 在生产硬件或等效功耗测试板上，轻睡眠和深睡眠平均电流达到性能目标。

## 9. 明确不属于 V1 的范围

- 温度、环境光、湿度和土壤传感器。
- Wi-Fi、云连接和远程控制。
- 电池供电、电量检测和低电量策略。
- 步进电机和多自由度运动。
- 麦克风、扬声器和语音交互。
- 双击、手势、力度和多点触摸。
- 手机原生 App。
- 用户账号、社交功能、数据分析和云端遥测。

这些能力只有在核心触摸互动闭环通过验证后，才进入后续版本规划。

## 10. 后续待决策项

以下项目不阻塞软件分层开发，但在硬件联调前必须确认：

- 具体 ESP32-C3 开发板或自研 PCB 型号。
- 舵机型号、机械零位、安全行程和速度上限。
- RGB LED 类型、数量和安装方式。
- 振动马达驱动方式及安全强度上限。
- 电容触摸方案及结构件对灵敏度的影响。
- BLE Service、Characteristic UUID 和最终二进制消息格式。
- OTA 签名算法、密钥烧录流程、分区大小和最大镜像尺寸。
- V1 PCB 的睡眠漏电预算、舵机电源开关方案和最终功耗基线。
