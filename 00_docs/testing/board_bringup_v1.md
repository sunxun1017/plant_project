# Plant V1 上板验证清单

## 1. 上板前需要确认

请在开始 ESP-IDF Adapter 和 BSP 联调前确认下表。未知项目不要用猜测值驱动真实硬件。

| 项目 | 需要的信息 |
| --- | --- |
| 主控 | ESP32-C3 具体模组、开发板或 PCB 型号，Flash 容量 |
| 舵机 | 型号、供电电压、PWM 频率、最小/中立/最大脉宽、安全角度、是否可断电释放 |
| 舵机电源 | 独立电源能力、峰值电流、电源开关 GPIO 及有效电平 |
| RGB 灯 | WS2812/RGB PWM 等类型、数量、数据或通道 GPIO、有效电平、亮度上限 |
| 振动马达 | 型号、MOS/驱动芯片、PWM GPIO、有效电平、安全占空比和最长连续工作时间 |
| 触摸 | 芯片内部触摸或外部触摸器件、输出 GPIO、有效电平、是否支持睡眠唤醒 |
| BLE | 设备名称、Service UUID、Characteristic UUID、期望 MTU |
| OTA | 分区表、最大固件尺寸、签名算法、公钥烧录方式、开发与生产密钥管理方式 |
| 低功耗 | 可在睡眠中关闭的电源域、触摸唤醒 GPIO、功耗测量点和调试接口影响 |

## 2. 安全准备

- 首次舵机测试先卸下连杆或限制机械负载，并使用限流电源。
- 未确认安全脉宽前，不发送最大行程命令。
- 舵机电源与 ESP32 电源容量分别核算，并保证公共地连接可靠。
- 振动马达和舵机不得由 GPIO 直接供电。
- 首次测试错误模式时，确认警告振动具有最大持续时间，不会无限运行。
- 正式 OTA 私钥不得放入固件仓库或烧录到设备；设备只保存验证所需信任根。

## 3. 建议联调顺序

### 3.1 基础启动

1. 烧录最小固件。
2. 验证串口日志、复位原因、Flash 容量和分区表。
3. 验证配置缺失时使用安全默认值。
4. 验证自检成功进入 `Idle`，自检失败进入 `Fault`。

### 3.2 单执行器测试

按以下顺序逐个启用，前一项稳定后再连接下一项：

1. RGB 灯：关闭、常亮、渐变、呼吸、错误闪烁。
2. 振动马达：轻脉冲、双脉冲、警告模式和强度上限。
3. 舵机：中立、休眠、安全最小与最大位置、停止和断电策略。
4. 触摸：单击、长按、防抖、睡眠唤醒。

每个 Adapter 都要验证越界输入被限制或拒绝，并能产生完成或失败事件。

### 3.3 行为闭环

依次验证：

- 休眠单击触发 `WakeUp`。
- 空闲单击触发 `Happy`。
- 长按触发 `Sleep`，再次操作可唤醒。
- 当前行为被 Stop、Sleep 和 Fault 按优先级中断。
- 行为完成事件携带正确 execution ID，过期事件不会结束新行为。
- 任一关键运动失败后舵机停止、振动停止并显示错误灯。

### 3.4 BLE

- 广播、连接、断开、重新连接。
- 命令应答和错误码。
- 查询生命周期、行为、功耗模式、唤醒原因和固件版本。
- 连接抖动不会重复播放 `Attention`。
- BLE 回调只投递数据，不直接操作执行器。

安装 `bleak` 后可用仓库工具执行基础联调：

```bash
python3 -m pip install bleak
python3 09_tools/protocol_tools/plant_ble_tool.py state
python3 09_tools/protocol_tools/plant_ble_tool.py behavior happy
python3 09_tools/protocol_tools/plant_ble_tool.py stop
```

Linux 若扫描不到设备，先确认当前用户有 BlueZ/D-Bus 权限。也可以用
`--address <BLE地址>` 跳过按设备名扫描。

### 3.5 低功耗

1. 完成 `Sleep` 后确认 RGB 灯、振动和舵机输出关闭。
2. 轻睡眠下验证触摸唤醒和 500–1000 ms 间隔的 BLE 广播；连接后验证链路不断开。
3. BLE 已连接、OTA 或 Flash 写入期间，深睡眠请求必须被拒绝。
4. 深睡眠下确认 BLE 关闭，并分别验证触摸、定时器和复位唤醒。
5. 验证唤醒原因记录正确。
6. 去除 USB 转串口等开发板附加负载影响后测量平均电流。

目标值：

- 轻睡眠、低频 BLE 广播：3.3 V 主电源轨平均电流不超过 5 mA。
- 深睡眠、BLE 关闭：3.3 V 主电源轨平均电流不超过 500 μA。

如果开发板无法达到目标，应分别记录 ESP32 模组电流和开发板附加电路电流，不能直接放宽产品 PCB 指标。

### 3.6 OTA

按以下矩阵验证：

| 用例 | 预期结果 |
| --- | --- |
| 正确型号、较新版本、有效签名 | 写入备用分区，验证后重启并确认新版本 |
| 错误产品或硬件版本 | 写入前拒绝，植物不移动 |
| 无签名或错误签名 | 拒绝激活，旧版本继续启动 |
| 传输分片乱序 | 返回错误，不写入错误偏移 |
| BLE 中途断开 | 放弃本次会话，旧版本仍有效 |
| 写入过程中断电 | 当前或上一已确认镜像可以启动 |
| 新版本首次启动失败 | Bootloader 自动回滚 |
| 版本降级 | 生产构建拒绝 |

OTA 开始前必须先完成安全休眠姿态；进入 `Updating` 后不得响应普通触摸行为或进入低功耗模式。
BLE 在等待安全姿态或接收分片期间断开时，固件会取消当前 OTA 会话；重新连接后必须从 offset 0 重新开始。
新镜像完成硬件初始化并稳定运行至少 10 秒后才确认有效；在确认前制造看门狗复位，验证 Bootloader 会回滚。

开发签名和生产签名策略确认后，可用工具按 496 字节自动分片：

```bash
# 先将 BoardConfig::Product::firmware_version 改为 0x00010001 并重新构建
python3 09_tools/protocol_tools/plant_ble_tool.py ota \
  /tmp/plant-ble-idf-build/plant_v1.bin --version 0x00010001
```

命令行 `--version` 必须与镜像编译时的 `BoardConfig::Product::firmware_version`
一致；它不是给既有二进制事后改版本号。

当前固件中的 `Signed Image` 字段只做流程前置校验，不替代 Secure Boot 或
ESP-IDF 签名验证；未完成生产密钥配置前只能用于开发板联调。

## 4. 稳定性验证

- 连续运行至少 24 小时。
- 循环执行 WakeUp、Happy、Sleep 至少 1000 次，观察舵机漂移、事件丢失和状态锁死。
- 循环 BLE 连接与断开至少 200 次。
- 至少完成 20 次 OTA，其中包含传输中断和启动回滚场景。
- 记录看门狗复位、任务栈余量、堆最低水位、错误码和执行器超时。

## 5. 当前主机端验证命令

```bash
cmake -S . -B /tmp/plant-project-build -DBUILD_TESTING=ON
cmake --build /tmp/plant-project-build --parallel
ctest --test-dir /tmp/plant-project-build --output-on-failure
python3 09_tools/protocol_tools/test_plant_ble_tool.py
```

主机测试通过只证明业务状态机和接口契约正确，不能替代真实执行器、BLE、睡眠电流和 Bootloader 回滚验证。
