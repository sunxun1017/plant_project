构建环境问题及处理：

- Windows 深层路径使 Mbed TLS 的依赖文件路径过长；使用较短的独立构建目录后解决。subst 被 IDF 解析回真实路径，单独映射盘符不够。
- esp_codec_dev 1.5.3 的 SPI 源文件缺少版本宏头文件；通过项目 CMake 对该组件定向预包含 `esp_idf_version.h`，没有改动 managed_components。
- PowerShell `-D` 参数整体引用，避免 `sdkconfig.zw_v1` 被拆开。

重新验证静态检查可使用已安装的 C++17 编译器：

```text
riscv32-esp-elf-g++ -std=c++17 -Wall -Wextra -Werror -fsyntax-only -I. 08_tests/unit/zw_v1_board_test.cpp
```

同一静态检查文件也被编入 `zw_v1` 目标，无需在真实板上运行测试代码。

## 追加的全仓检查与修复

- 检查了行为/生命周期、OTA、通信、增长调度、灯光仲裁、振动和新板电源/中断路径。
- 修复普通行为立即语义完成后，Idle 状态下 StopBehavior 不停止残留灯光/振动的问题；停止时尝试全部输出，返回第一个错误，并将故障传递至生命周期，不重新启动警告振动。
- 新增服务级和 V2 命令入口回归测试。服务级测试在修改前出现 9 个失败检查，修复后全部通过；命令入口验证 Idle 停止及 HapticFailure 故障传播。
- 修复 BLE 断线/主机复位后残留接收命令：清队列，并为帧增加连接代次；出队时复查连接、加密、绑定和代次。已经交给业务层执行的命令不由接收队列撤销。BLE 重连的无线实测仍待开发板验证。
- 将 ZW 引脚/CRC 静态检查纳入主机 CMake 测试构建。
- WSL Ubuntu 22.04 / GCC 11.4：全量主机测试通过（CTest 的一个可执行文件包含全部单元及集成测试）。
- ESP-IDF 6.1：旧 V2 固件完整构建通过，ZW 默认保护配置构建通过。V2 构建只验证兼容性，不适用于此 ZW PCB。
- 未进行烧录、真实 BLE 重连、实际电流或舵机标定测试；不能据此认定产品已通过量产验收。
