## 必须先解决的硬件问题

### 1. PNP 基极缺少串联限流

Q8、Q9、Q10、Q12、Q14、Q15 的基极直接接 PCF8574 输出。例如 PCB 中 Q9.1、U4.10 同属 EXPIO4；R48 在基极和 ESP_3V3 之间，是基极—发射极上拉，不是串联基极电阻。其余五路同类连接。

拉低扩展 IO 后，电流路径是电源 → PNP 发射结 → PCF8574 下拉管，缺少明确的串联限流。不能把 PCF8574 的灌电流能力当作精确的恒流保护。应为每一路按集电极负载、强迫电流增益及扩展器单脚/总电流约束计算基极电阻，或改成具有确定输入电流、关断漏电指标的负载开关/MOS 驱动。修板后再测量每一路开启与关闭的电流。

固件默认 `CONFIG_ZW_BOARD_POWER_PATH_VERIFIED=n`，在初始化电源 IO 前返回，避免自动激活上述电流路径。这是本次根据实际连接加的硬件保护，不是量产就绪标记。

### 2. 关断电源域没有对应的总线隔离

PCB 中 R16/R17 将 I²C 上拉至 ESP_3V31；U3 由 VDD33 供电。VDD33 断电后，SDA/SCL 仍可能从常供电域向 U3 注入电流。U2 的 AVDD 直接接 VDD33，PVDD/DVDD 则经过 Q1 与磁珠：只关 EXPIO6 并不能保证整个 ES8311 断电，同时数字总线仍连接。

这既可能抬高休眠电流，也会使启动、I²C ACK 和传感器状态变得不可靠。需要核查器件掉电输入容限及所有跨域信号，采用总线隔离/同域上拉/完整电源域切换方案。仅将 MCU 的 SDA/SCL 改成输入不能消除外部上拉。

联调代码在通过硬件检查开关后保留 VDD33 和 ES8311 数字供电，使用 codec 软件 standby，停止 I²S，关闭舵机/雷达/振动/充电使能。PCF8574 的静态输出为 `0xAE`。禁止通过当前 API 直接关闭 VDD33 或 codec 数字电源。此策略规避主动制造半掉电状态，**不承诺整板达到微安级**；PNP 驱动级静态电流等仍须实测。

### 3. 舵机反馈不能照搬旧板归一化和故障判定

R30 为 1 kΩ 电位器，PCB 上端接 ESP_3V31，下端通过 Q11 接地，滑臂经 R7 接 GPIO3。Q11 与舵机电源共用 SERVO_PEN。关闭舵机时，电位器下端开路，滑臂可能接近高电平，不能据此判为滑臂开路，更不能认为当前位置仍然有效。

ESP32-C3 在最高衰减档的有效测量范围为约 0–2500 mV。电位器滑臂可接近 3.3 V，超出有效范围会饱和；不能把 4095 简单对应为 3.3 V。需要调整分压/反馈电路、标定有效机械范围，并验证上电稳定时间。当前仅提供有供电前提的原始 ADC 读取，不移植未经标定的 700–2300 μs 自动动作。

### 4. 充电和马达仍缺少产品参数

BQ24259 是充电及电源路径芯片，不是 MAX17048 电量计；没有可直接读取的电池电压 ADC/SOC。固件读取芯片身份、REG08 状态和两次 REG09（历史/当前故障），不伪造电量百分比。当前版本不开放充电使能，不修改充电电流、终止电压或运输模式寄存器。

发版 PCB 的 CN3 为三针：1=保护侧电池负端，2=BAT_NTC，3=VBAT；与 PDF 的两针电池座不同。BOM 未给出电池容量、允许充电电流、NTC B 值和舵机型号。BQ24259 的 PSEL/OTG 未接外部网络，需要在修订板上确定输入电源识别电平和限流策略。R56 的输入限流不能替代电池充电电流配置。

注意：QON 与 TS 同网本身不能直接判为接错。TI 手册允许在不使用 QON 功能时将其接到 TS。当前不实现 BATFET ship mode，避免把 MCU 深睡与整机电池断开混为一谈。

振动马达 BOM 标称 3 V，实际接 VSYS，并由达林顿管驱动；必须测量电机端电压、电流和温升。舵机 Q5 的额定能力需与堵转电流匹配，不能只按空载电流选型。

| --- | --- | --- | --- |
| P0 | GND | 已接地，不作普通输入 | 输出锁存保持 0 |
| P1 | EXPIO1 | 振动 | 低 |
| P2 | EXPIO2 | 雷达供电 | 低 |
| P3 | EXPIO3 | 舵机 + 电位器使能 | 低 |
| P4 | EXPIO4 | VDD33 总电源 | 低 |
| P5 | EXPIO5 | TTP223 输出 | 触摸为低；锁存必须保持 1 |
| P6 | EXPIO6 | ES8311 数字电源控制 | 低 |
| P7 | EXPIO7 | 充电使能，经 Q12/Q13 | 低 |

TTP223 的引脚 4 接高、6 接地，因此是低有效直接输出，而非每次触摸翻转的自锁模式。PCF8574 中断代表端口变化，GPIO2 本身不能用来判断是否正在触摸。输出更新不得把读取的端口值写回，否则触摸期间可能把 P5 锁成低输出。

I²C 使用 100 kHz，7-bit 地址为 PCF8574 `0x20`、GXHT40-AD `0x44`、BQ24259 `0x6B`、ES8311 `0x18`。esp_codec_dev 的 control 配置采用 8-bit 地址，因此传 `0x30`。BOM 中 PCF8574 的 2.4 MHz 描述不作为总线频率依据。还需核对实际采购的 UMW 料号、封装与引脚定义，而不是仅依赖采购表的通用描述。

## 低功耗策略及验收

1. 修正硬件后先验证每一路电源状态和 PCF8574 输出电流。用限流电源，不连接舵机执行机构进行初始验证。
2. 检查 GPIO2 中断空闲为高，触摸按下/松开都能清中断。持续触摸和 INT 卡低不能造成忙循环或无限唤醒。
3. 默认联调循环按触摸中断或 30 秒温湿度期限运行，不使用固定 20 ms 全局轮询。去抖期间才缩短等待。
4. 低功耗使用 DFS + 自动 light sleep；可选深睡测试在启动 30 秒后进入、60 秒定时或 GPIO2 唤醒。深睡是重新启动，不维持 BLE 连接。
5. 入睡前 codec standby、停止 I²S、关闭执行器、读取 PCF8574 清中断，再检查真实触摸及 INT。已有触摸或卡低中断时推迟深睡。
6. 电流分别测量：MCU 活跃、触摸待机、codec standby、音频采样、马达/舵机工作、深睡。USB/JTAG、供电方式、电池电压和采样仪器量程必须记录。
7. 平均电流使用各状态实测电流乘占空比相加；续航还需电池可用容量、转换损耗和自放电数据。当前没有实测电流或续航结论。

未实现/未验证：实板通讯、舵机闭环及行程标定、雷达协议、持续语音/语音识别、RGB/光照硬件替代方案、真实 SOC、充电参数、旧业务 BLE/OTA 接入、整机功耗与热测试。旧 `v2` 业务和协议未改成伪成功的空驱动。
